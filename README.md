# Анализ больших данных - Лабораторная работа №1 - Нормализация данных в снежинку

## Введение

Целью работы была разработка процесса переноса плоских данных из CSV-файлов в PostgreSQL с последующим преобразованием в аналитическую архитектуру типа "Снежинка". Это позволяет оптимизировать хранение, устранить избыточность и подготовить данные для аналитики.

## Основные этапы работы

### 1. Подготовка инфраструктуры

Работа велась с использованием Docker и Docker Compose. Был создан контейнер с PostgreSQL 15. Для автоматизации процесса были настроены тома (volumes):

- Папка с 10 исходными CSV-файлами (всего 10 000 строк) была проброшена в контейнер.
- SQL-скрипты помещены в директорию `/docker-entrypoint-initdb.d/`, что позволило базе данных автоматически инициализировать схему и загрузить данные при первом запуске (`docker-compose up`).

### 2. Импорт «сырых» данных

Первым делом была создана таблица `staging_raw_data`, структура которой полностью повторяет структуру CSV-файлов. С помощью команды `COPY` данные из 10 файлов были объединены в этой единой "грязной" таблице для дальнейшей обработки.

### 3. Составление модели «Снежинка»

- Центральная таблица фактов `sales_records` — хранит идентификаторы участников сделки и количественные показатели.
- `dim_customers` — данные о покупателях и их питомцах.
- `dim_products` — каталог товаров.
- `dim_stores` — информация о магазинах.
- `dim_suppliers` — данные о поставщиках товаров.
- `dim_locations` — общая таблица локаций, хранит города, страны, индексы.
- `dim_prod_types` — категории товаров.

### 4. Миграция данных (ETL-процесс)

С помощью SQL-запросов (`INSERT INTO ... SELECT DISTINCT`) данные из сырой таблицы были распределены по новой схеме. Для географии использовался `UNION`, чтобы собрать уникальные локации из разных столбцов исходного файла.

## От чего я избавился в процессе работы?

### 1. Нормализация географических данных

В исходных файлах было много избыточной информации: номера офисов (`store_location`), конкретные адреса зданий (`supplier_address`). Я привёл данные до уровня города и страны, вынеся их в единое измерение `dim_locations`. От этой детализации я отказался, так как для аналитических отчётов она не требуется.

### 2. Неактуальные поля

Текстовые описания товаров, детали питомцев, данные о конкретных продавцах были исключены как избыточные данные для этой финансовой модели.

### 3. Мусорные ID

Исходные колонки `sale_customer_id` и другие оказались простыми номерами строк. Я заменил их на полноценные первичные ключи.

## Проверка результатов

Для проверки корректной работы модели был создан файл `analysis.sql` с различными проверочными запросами.

## Инструкция по запуску

1. Выполнить команду:
   ```bash
   docker-compose up -d
   ```

2. База будет доступна по адресу `localhost:5433`, пользователь: `admin`, пароль: `4321`.

3. Выполнить проверочные запросы из файла `analysis.sql` для подтверждения целостности данных.

## Вывод

В ходе лабораторной работы была успешно реализована трансформация "сырых" данных в аналитическую модель "Снежинка". В ней нет лишних дубликатов, соблюдена логика связей, а разделение адресов и категорий по отдельным таблицам позволило сэкономить место и сделать базу удобной для быстрой аналитики.
